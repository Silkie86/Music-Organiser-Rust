# Space: where Rust differs from the C# app

The C# app's `Core/Space` is the reference (`DiskSpace`, `SongSpace`, `AppFiles`, `RecycleBin`). Each difference is
listed with a verdict: **better** (on purpose), **same idea, new shape**, or **not yet**.

## Measuring

| What | C# | Rust | Verdict |
|---|---|---|---|
| Walking a folder | one thread, file by file | a level of folders at a time over every core of the pool it's called in (rule 21) | better |
| Links, OneDrive online-only files | not followed / left out of sizes | the same | same |
| A file with two names (a hard link) | counted once for each name | a folder's size (`measure`) counts it once on a Mac or Linux; Windows can't tell from here, and the other walks (a song's space report, Clean up's look) still count each name | better |
| `size_text` rounding | .NET formatting | the same, halves rounded up as .NET does | same |
| Stopping part way | `CancellationToken` | a stop flag, looked at before each folder is read and every 256 entries in one; a stopped measure says `Stopped` rather than giving a part answer | same idea, new shape |
| Compact line notes | text built when measured | a `note()` worked out from the line's fields (kind, time, the save it copies) | same idea, new shape |

## Clean up

| What | C# | Rust | Verdict |
|---|---|---|---|
| Checking before removing | the list was trusted as measured | every picked line is checked by a guard at the preview **and again** just before it goes: inside a project folder, not a project folder itself, not in or holding a sample folder, not a sound any project uses by name, not a song's newest save, really the kind the line says (a save, an autosave below the project folder, Studio One's Cache folder, audio), not a link, not on a network drive (no Recycle Bin; on a Mac or Linux, network shares mounted into a folder too) | better |
| A copy and its twin | the measure never lists both | a copy whose twin is also picked stays; at clean-up a copy only goes while its twin is still byte for byte the same | better |
| Changed since you looked | removed anyway | a file whose size or time isn't what the list measured stays, and so does a file that changed between the preview and the clean-up (even at the same size). Studio One's Cache folder is compared by the folder itself only (a file rewritten deep inside doesn't count): it's rebuilt anyway | better |
| Links | the path as written | paths are checked as written and as they really are (links, `..` and mapped drives worked out): a link out of the project folder, into a sample folder, or a copy whose twin is a link to it, stays; a song folder that's a link isn't the song's own | better |
| Undo | find it in the Recycle Bin yourself | after a clean-up each thing is found in the bin (one that isn't is reported: Windows removes for good, after asking, what's too big for its bin); the `Done` list, kept by the app, is what `undo` puts back; on a Mac, Finder's Put Back. Windows lists a file without its ending when Explorer hides endings (as it does at first): it's still found, by the ending of the file the bin keeps, and comes back under its whole name. Undoing a clean-up again never puts back something binned later from the same place, nor something the bin gave the same name later (Linux names a thing in the Trash after the one before it, once that's gone): what the bin calls it and when the bin says it went in are both kept when it's found there (Linux keeps that time without the time zone, so the computer's zone then is kept too, and the time is read as the Trash reads it in the zone it's in now), and each thing in the bin is put back for one line only | better |
| Thinning, default | the setting's default is 3 hours | the same; and the newest save is never thinned even when another was written at the same moment (C# could thin it) | better |
| Removing for good | never: Recycle Bin only, Windows asks before deleting anything too big for it | the same (the `trash` library sets the same Windows flags) | same |
| What the app put in the Recycle Bin | never emptied by the app; each clean-up says its files are in the bin, with a button to open it | never emptied by the app either (Solomon, 3 Nov 2026: "leave it to me with a warning"), and the Space page says how much of what the app put there is still in the bin, on which drive, since when, and that it takes room until you empty the bin (`in_bin::remind`, from every clean-up's `Done` list the app keeps; what's emptied or put back doesn't count, and each thing in the bin counts once: where two lines could be it, for the one sent later). A Mac's Trash can't be looked in, so there it's all the app put there | better |
| What the Recycle Bin can't keep | each clean-up checked network drives and OneDrive files itself; a USB stick or memory card wasn't checked, so Windows asked to delete for good | each clean-up still checks them itself, and the one route every clean-up sends through (`Sending::send`) checks once more: anything on a network drive or (on Windows) a USB stick or memory card, or a OneDrive file that's only online (or a folder holding one, on Windows; a folder in it that can't be read, such as one whose list of files is still only online while OneDrive isn't running, counts as can't tell, so it stays), stays with why, whichever clean-up it came from (a moved folder's old copy on a network drive now stays: delete it yourself) | better |
| Sending, whichever clean-up | n/a | the one route also never sends a link (the bin would take the link, but the administrator step where it leads); sends one thing reached two ways once; and once you press Stop, what hasn't gone stays. What waits for the administrator step is checked once more just before Windows asks: still not a link, and still where it was really (a folder on the way that leads elsewhere now keeps it) | better |
| Files Windows guards | binned in one administrator step (plugin clean-up), as listed | the same for songs and plugins: one administrator step at the end for all of them, so Windows asks once. Each is checked again just before Windows asks, and the step leaves anything that changed while it asked; what's gone afterwards is what counts as removed (see [Administrator step](#administrator-step)) | better |

## Plugins

| What | C# | Rust | Verdict |
|---|---|---|---|
| Plugin files under linked folders | .NET's walk goes through links | the same, each real folder once, so a link back up can't loop | same |
| A family's letters | .NET `char.IsLetterOrDigit` | Rust's alphabetic or numeric: the same for every name seen; a few rare scripts' marks count as letters too | same idea, new shape |
| Folders in a data root, order | as the folder lists them | by name, so two runs give the same order | better |
| Measured when | stored with each plugin | not kept here: the caller knows when it measured (rule 23) | same idea, new shape |
| A folder naming a version | the comment says "Serum 2 Presets" is Serum 2's alone, but `Family` strips the version, so Serum and Serum 2 shared it | a folder naming a version ("Kontakt 8 Library", "Serum 2 Presets") is that version's alone; one naming none ("Kontakt Library") stays shared | better |
| A folder you added | counted for you, and for any other plugin whose guess took it too (twice) | shared with any other plugin whose guess takes it, or that has it added too, so it's counted once and stays on one's clean-up card while the other is used; rule it out for the other to make it yours alone. One you added inside another counted folder (a maker's, say) is taken off that one, so it's counted once | better |
| A plugin folder ruled out inside a maker's folder | still taken off the maker's folder, so counted nowhere | stays part of the maker's folder | better |
| A plugin file that's a link | measured as the link (nothing) | measured where it really is; a link to a file the plugin has listed already isn't counted again | better |
| Linux VST2 plugins | `.so` files not found | found | better |
| Documents | Windows' own Documents, wherever it's moved | the same (Windows' known folders) | same |
| Spare copies: same plugin? | one family anywhere inside the other ("Serum FX" took Serum's projects); versions ignored, so Ozone 9's projects counted Ozone 11's VST2 | by name as the Plugins page groups them (endings like "x64" and "(VST3)" ignored, but versions not: Ozone 9 and Ozone 11, TR-808 and TR-909 are different plugins), equal, or one with its maker in front ("FabFilter Pro-Q 3" and "Pro-Q 3") | better |
| Spare copies' reason | text stored with each copy | a `Why` worked out into text when shown | same idea, new shape |
| Is Pro Tools here (are AAX copies spare)? | its usual folder | its usual folder; on Windows also any Pro Tools among the installed programs (another drive, or another name); on a Mac any Pro Tools app ("Pro Tools First", …) in the Applications folders or a folder in them. One left listed after it was removed still counts, so AAX copies stay | better |
| Removing spare copies | found again against your projects as they are now, then to the Recycle Bin, Windows asking once for Program Files | the same, and each is also checked just before it goes: still there, a plugin file or bundle of its format, not a link, not only online in OneDrive, not on a network drive, holding just what it held when found (each file, its size and time, and where it really is: an update since, even one of the same size, or a folder on the way that leads elsewhere now, keeps it); and the copy your projects use must still be there and hold something here (a link whose file has gone, an empty bundle left behind or one only online doesn't count). When it isn't spare any more, it says why (Pro Tools may be installed since, or a project saved since). One file picked twice by two paths (a linked folder) goes once. A copy that can't go (a link, on a network drive, only online, unreadable) is still listed, with `can_remove` false. The ones Windows guards are checked again just before it asks, and once more by the administrator step | better |

|---|---|---|---|

| A plugin the library doesn't know | counted as having no projects when shared, as used when held | counted as used everywhere | better (safer) |

| Checked again before it goes | the card's look again (samples, OneDrive) | every rule again, against the plugin's folders as they are now, and the folder must hold just what it held when you looked: the same files, sizes and times (a preset renamed or saved again at the same size counts; the files Finder and Explorer make by themselves don't) | better |
| A folder inside another you picked | n/a (one folder at a time) | goes with it, once, and is listed as gone with it; the room freed (`freed`, and what the clean-up reports) counts everything inside once | better |

| Undo | Recycle Bin by hand | the same `Done` list and `undo` as songs | better |

## Uninstallers

| What | C# | Rust | Verdict |
|---|---|---|---|
| Which programs, which first | Windows' list of installed programs (both hives, 64- and 32-bit), matched by family, maker and version; a DAW's never; another version's last | the same, checked on the C# app's own test cases | same |
| Starting one | .NET's shell start, so Windows asks its administrator question when the uninstaller needs it | PowerShell's `Start-Process` (Windows' own copy), which does the same; the program and what's passed to it go in as settings, never as script, so nothing in them can run as a command | same idea, new shape |
| Waiting for it | waits for the program started; one that copies itself to Temp and starts the copy (NSIS) seems done at once | waits for it and what it starts (so also for a browser it opens, if the browser wasn't open) | better |
| How it went | not told | told: done, cancelled, or ended with a code (so it may not have finished); the plugin list is checked again either way | better |
| `%ProgramFiles%` in the command | filled in as Windows' list is read | the same | same |
| Saying no to Windows' question | told | told, in any language Windows speaks | same |

## Moving plugin data to another drive

| What | C# | Rust | Verdict |
|---|---|---|---|
| How | copy, check every file's size, rename the original to "… (old copy)", a junction in its place; undo freshens the old copy and swaps back | the same steps, and the same checks before (gone, a link already, inside a moved folder, old copy there, inside the one moved, same drive, name taken, OneDrive files only online, room plus 2 GB) | same |
| Room on the other drive | the folder's size as measured, plus 2 GB, on the drive the path names | counted again (the size measured earlier only when it can't be), each file and folder as the drive keeps it, in whole pieces (128 KB each on a big exFAT drive, so a folder of many small presets takes far more there), leaving out the old copies of folders moved from inside it (they aren't copied), plus 2 GB, on the drive the folder really goes to (a link on the way is followed). The same when moving back or linking again | better |
| A big file while it copies | copied in one go: Stop waits for its end, and the bar doesn't move meanwhile | a file of 64 MB or more goes 8 MB at a time, so Stop takes hold within a piece and the bar moves through it. Smaller ones are copied by the system in one go. On Windows a big file keeps its marks (read-only, hidden) as before; on a Mac its extended attributes (Finder tags, say) aren't copied | better |
| Where moves are kept | `library.db` setting `space_moved_folders` (JSON) | the same JSON, read and written by `parse_moved` and `moved_json`, so moves made by either app are known to both | same |
| A network drive picked | refused on Windows, by the drive's type | refused on every system, also when the folder picked leads there through a link | better |
| The folder picked isn't there | made | refused, so a mistyped folder isn't made | better |
| A folder of that name appears while copying | copied into | the copy is made as a new folder first, so it stops instead | better |
| Files saved while it copies | only those in folders not yet copied go across | a second pass after the copy takes what was added or changed meanwhile; and on Windows each file is looked at again just before it's copied, so one that changed since its folder was listed (Windows gives a listing's sizes as they were then) copies whole instead of stopping the move (elsewhere a listing looks at each file as it's asked) | better |
| A file that goes while it copies (a plugin's lock file) | stops the move | passed over, while the folder being moved is still there: once it isn't (its drive unplugged, or the folder deleted), or something can't be read, the move stops, rather than taking what's still to be copied for deleted. One that turns into a folder or a link just as it's to be copied is passed over too, for the next pass to copy as what it is, but in the last pass (nothing looks again before the copy goes into use) it stops the move, as it would be missing from the copy. A folder that turns into a link (or a file) as the copy goes, or one above it, or the folder being moved itself, stops the move in any pass (its folder in the copy is made already), and what the link leads to is never copied as the plugin's: each folder, and every one above it, is looked at name by name as its turn comes and again once all of it is read (a folder renamed in other capitals, on a drive that doesn't tell them apart, is the same folder). Files are read by their paths (Windows has no other way the app can use), so one read just as its folder turns into a link can come through the link: a copy the move made goes when it stops, and into a folder of yours (moving back, linking again) files go in, and links are made, only once their folder is found still real after they were read. The folder being moved is looked at where it really is as the first pass begins: each pass after stops when it leads somewhere else (moving back from a copy moved on and linked, whose link was pointed elsewhere meanwhile), and the swap doesn't happen when it isn't a real folder by then. A file or folder the first pass copied that's a link by the last pass stops the move too. A link the first pass made again, where the folder has a file or a folder by the last pass (a plugin saved over its link), goes, and what's there then is copied. In a folder of yours what's there stays | better |
| A pipe or a socket in the folder, or one a link in it leads to (a Mac and Linux) | none on Windows (its own socket files, which are rare, read as files) | passed over, as it holds nothing to copy (reading a pipe would wait for ever), and not taken for something only in the old copy. A link to one is made again as a link where the drive holds links; where it doesn't, it's passed over too (counting the room doesn't refuse it as a link the drive can't hold), and isn't taken for something only in the old copy either. Windows' socket files are copied as any file is, and the move stops if one can't be, as before | better |
| Two names that differ only in capitals, to a drive that doesn't tell them apart | the second one stops the copy | the same; and moving back or linking again into a folder of yours on such a drive (from a drive that tells them apart) stops at the second too, saying to rename one, where before one would be taken for the other (kept aside as yours, or replaced). Found while counting the room (also when the drive's room can't be told), before anything there changes, when one of them is there already. Where the drive tells them apart both go, as before | better |
| A link inside worded from where it sits ("..\Shared") | kept as worded, so on Mac it would lead somewhere else from the other drive | made again leading to the same real place | better |
| A link inside leading to another place in the moved folder | made again to the old place, so after moving back it can lead to the other drive | leads to the same place in the copy, wherever the copy ends up | better |
| A folder link inside that Windows won't make again | the copy stops | the same, and a junction Windows only half made (it starts from an empty folder) goes, so trying again doesn't take that folder for the link. Where the drive it goes to holds no links (told by the drive's kind, nothing written to find out: on Windows only NTFS, ReFS and Btrfs drives count as holding them, from Windows' list of drives, read at most once a second, so FAT, FAT32, exFAT and kinds the app doesn't know (a Mac or Linux drive read through another's driver) are refused up front, not part way; a network drive, a CD or a DVD isn't in that list, and counts as holding them; on Linux exFAT and FAT drives don't; a Mac keeps links even on its FAT drives, as small files, so it isn't asked there), a link to a folder, or one that leads nowhere now, is found while counting the room, before anything changes: before a move copies, and before moving back or linking again changes a folder of yours, also when the drive's room can't be told | better |
| A folder on a drive that holds no links (exFAT, FAT32, and on Windows a kind the app doesn't know) | not checked: it copies it all, then the link that takes its place can't be made at the swap | refused before anything is copied, as the link that takes its place couldn't be made there (`NoLinksHere`) | better |
| A link inside that leads nowhere now (a drive not plugged in) | made again | made again (on Windows a folder link as a junction; a file link only where Windows allows one, otherwise left out and named by the check before the old copy is deleted) | same |
| A file link inside, where Windows won't make one again (without Developer Mode) | the file it leads to is copied instead, as it is | the file it leads to is copied as any file is: its time kept and checked whole, under a temporary name first into a folder of yours (written through before it goes in), a big one a piece at a time so Stop and the progress bar work, and copied again by the next pass when it changed meanwhile (a link that leads to no file by then stops the move); on Windows the room a move needs counts that file. One that's only online in OneDrive isn't downloaded to be copied: the move stops before the swap, and says which file to keep on the device. Counting the room asks Windows once whether it makes file links for the app (by making one in the temporary folder and removing it: that takes Developer Mode), and the drive the copy goes to must hold links (told as for a folder link, above; on one that doesn't, the file is counted on every system); where the link can't be made, that's said before anything changes: before a move copies, and before moving back or linking again changes a folder of yours, also when the drive's room can't be told | better |
| Deleting the old copy | when the link reaches the copy | also never while the link leads into it, or the copy is in it (a link pointed back at the old copy once the other drive went); only when nothing is only in the old copy, or newer there (`only_in_old_copy`, which the app shows first; you can still say you're sure), and when the old copies of folders moved from inside it earlier still have working links. An old copy that's a link now stays, and says so (where it leads is left alone) | better |
| Moving back with the old copy there | copies files that are newer on the other drive into it | copies files that are new or differ in size or time (an update can bring an older time), each under a temporary name first, so one that fails leaves the old file whole; the old copy's own newer files are kept in "… (newer files from the old copy)" beside the folder, never replaced; a second pass takes what was saved meanwhile; only with room for it plus 2 GB. Stopped or failing part way, it says the old copy was partly brought up to date and where its newer files are (or that nothing was moved, when nothing in the old copy had changed yet); trying again keeps them in a folder of its own, and `kept_beside` lists both meanwhile. A file that can't go in after yours was kept aside puts yours back. What would stop it part way (two names that differ only in capitals when one of them is in the old copy already, a folder where the old copy has a file, a link the drive can't hold) is found while the room is counted, before anything changes, also when the drive's room can't be told | better |
| Moving back once the old copy is deleted | copies the folder back | also checks this drive has room for it plus 2 GB, and that the link still leads to the copy the move made | better |
| Moving a folder whose link an update replaced with a real folder | moves it again, and the first copy is forgotten | refused, pointing at linking again (`after_move::link_again`), which puts it right | better |
| A folder Windows won't rename (access denied) | asks Windows' administrator question and does that one step as administrator; if even that's refused, "Windows wouldn't allow it even as administrator" | the same, and Windows asks before copying too (a move, or linking again after an update): the folder is renamed and straight back as administrator, so a folder even the administrator can't rename (the DAW has a file in it open) is found before a long copy, not after it. It's only asked once there's known to be room. Then the copy is made as you, and Windows asks again for the swap (and once for moving back, which isn't checked first: what it renames is the link and the copy brought back). When moving, a no at either question means nothing has moved (a copy already made goes); when linking again, a no at the swap leaves the update's files added to the copy on the other drive (the ones they replaced kept beside it) and says so. If even the administrator is refused, it says that something is probably using it and to close the DAW, the plugin and any window showing it (Windows refuses for that too). On a Mac or Linux (no question to ask) it says so before copying anything | better (two questions, but no wasted copy) |
| Something fails half-way and the folder can't get its name back | can say nothing was moved while the folder is left as "… (old copy)" or without its link | says what to rename back, and keeps every copy that holds the files | better |
| The app or the computer stops while it copies (a crash, a power cut) | the half copy stays on the other drive, and the next try says it "is there already. Pick another folder, or rename that one." | every copy a move makes as a new folder (moving, moving back once the old copy is gone, moving the folder the moved folders live in) holds a marker, "Music Organiser - copy not finished.txt", until it's in use; just before it goes into use (the swap, or pointing the links at it) the marker says so (Solomon, 3 Nov 2026). The next try at the same copy clears its half copy first, for good (it only ever holds copies), and counts its room as free, also once the drive has another letter (another drive may have its old one, with a folder at the same place, or one that can't be read now: a card reader with no card in), and for a copy made through a folder link (the marker says where the copy really is too); `half_copy::half_copies` finds the others for the Space page and `half_copy::clear` clears one. Each only once it's checked again just before: nothing in the app is making or clearing a copy there now; it never started going into use; the folder it copies from is still there, and nothing leads into the copy; moving back, the link still leads to the copy on the other drive; and everything in it has its twin in the folder (file for file, or the file a file link leads to; folder for folder; link for link), none of its files newer than their twins but the one it was writing. Otherwise it stays, and says why; cut off as it swapped, it says what to rename back. A marker in a copy that's in use (the app stopped just after the swap), or in a folder renamed or moved since on its drive (also when a link of the copy's name leads to it), is all that goes. Clearing stops when you press Stop, and a copy whose swap fails goes as one that stops does, its marker first saying it isn't going into use after all: either way, what's left is still a half copy, cleared the next time. The marker goes last; a file Explorer or Finder writes into the emptied folder just then goes too, and if anything else is in it by then the folder stays, with its marker. Removing never follows a link it meets (something swapping one of its folders for a link while it's removed could still lead it through: Rust's standard library can't remove things by a folder it holds open). A half copy that stays is measured whole for the Space page, what's only in it too, in the same walk as the check | better |
| Writing the copy through to the disk | left to Windows, which writes a copied file's bytes to the disk when it gets to them | just before a copy goes into use (moving, moving back, moving the folder the moved folders live in, linking again), every big file it wrote (64 MB or more) and the small files written in its last two minutes (up to the last 20,000 of them) are written through to the disk, each once, so a power cut just after the swap can't leave the plugin using files whose bytes never reached the disk. A file going into a folder of yours (moving back into the old copy, linking again into the copy on the other drive) is written through before it replaces the one there, so a cut-off try never leaves one that looks whole but isn't: up to 256 of them (or 1 GB) wait under their temporary names, are written through together on all the cores, then go in, and one that couldn't be written through then is again just before the swap. Yours that's kept aside goes there only as the new one goes in (and comes back if the new one can't), so a stop leaves the rest where they were. A temporary file an earlier try left isn't copied on (moving, moving back, linking again), nor counted as only in the old copy. Small files written earlier are taken to be on the disk by then (Windows writes what's waiting within seconds). Stop works meanwhile, and the copy doesn't go into use then; the progress bar stays full while it writes | better |

## After a move

| What | C# | Rust | Verdict |
|---|---|---|---|
| Lost, replaced by an update, doubled by a later move | found the same way | the same (`lost`, `replaced`, `doubled`); the Rust move keeps links inside as links, so it never makes doubled ones itself | same |
| Folders left behind | `library.db` setting `space_old_homes` (JSON) | the same JSON (`parse_old_homes`, `old_homes_json`), plus where its files went (`Copy`) and what it holds (`Kind`), written only when there's something to say; the C# app skips over them when it reads | same, and more |
| Linking again after an update | new and newer files join the copy on the other drive, then the folder is set aside and the link goes back | files that are new or differ join it, each under a temporary name first; every file of the copy that's replaced is kept first in "… (kept from before)" beside it and listed back (the update's file may be newer, but yours was the one in use); a second pass takes what was saved meanwhile; only with room for it; a stop or failure partway says what's where (or that nothing was moved, when nothing in the copy had changed yet) | better |
| What linking again set aside or kept | the folder set aside is listed to delete | the same, at its real place (a second copy inside a moved folder is on the other drive); the files kept from before are listed too (and found beside the copy, `kept_beside`, even after a try that stopped partway), and since there's nothing to check them against they go only once you say you're sure | better |
| Deleting a folder left behind | when no moved folder or link is still in it | the same, and only when nothing is only in it, or newer there (`only_in_old_home`, shown first; you can still say you're sure), and not when a link is in its place now (removing that frees nothing) | better |
| Reminding you of old copies | a card over the Plugins list while any old copy or folder left behind can go ("2 old copies left after moving folders"), with the sizes measured when they moved | every time, for as long as any is there (Solomon, 3 Nov 2026: "should always remind about old copies"), each measured now, biggest first, with when it moved and why one can't go yet (`old_copies::remind`): the old copies, the folders left behind, the files kept aside (`kept_beside`), and an old copy whose move was never kept (the app stopped just after the swap), found beside its link and taken in as a move so it goes the same guarded way. A "… (old copy)" with no link beside it, or whose link leads back into it, is listed too, and stays, saying what it may be. The headline counts only what can go, with the room it takes, and how many can't go yet: "2 old copies left after moving folders (64.2 GB), and 1 that can't go yet" | better |
| Moving the folder the moved folders live in | renamed on the same drive, then every link pointed at the new place, outer ones first; copied and checked to another drive | to another drive the same, with the checks a move has (a link, inside itself, network drive, name taken, OneDrive, room) and a second pass.
